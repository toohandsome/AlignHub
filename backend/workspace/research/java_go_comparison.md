# Java vs Go 技术选型对比

## 并发模型
- Java: 线程池 + 异步框架，上下文切换成本高，需精细化管理
- Go: CSP 并发模型 (goroutine + channel)，天然支持高并发与故障隔离

## 生态与框架
- Java: 成熟的 JVM 生态，Spring 等框架适合复杂业务
- Go: 轻量级标准库，适合构建高效 API 与微服务

## 稳定性与可预测性
- Java: GC 暂停可能影响延迟，需调优；熔断机制依赖第三方库；适合已有的复杂业务系统
- Go: 低延迟 GC，原生支持超时控制与并发安全，错误处理更显式；适合新建的高并发 API 服务

## 决策建议
- 新建高并发 API 服务：优先考虑 Go，以保证系统稳定性与可预测性。
- 已有复杂 Java 项目：深化 Java 并发优化，降低迁移成本。
